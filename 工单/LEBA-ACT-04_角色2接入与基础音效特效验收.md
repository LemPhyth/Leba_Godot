## 1. 编号、任务范围与开发目标

编号：LEBA-ACT-04。口头称呼与内部编号的对应：第一个角色为`crt_0`，第二个角色为`crt_1`，**本轮第三个角色为`crt_2`**。

用户已确认ACT-03阶段验收通过，第二个角色各技能可正常释放；同时反馈其音效基本未接入、Q特效引用错误。本轮主线是恢复第三个角色，并补修这两项已知基础接线问题，不重新否定上一轮阶段验收。

本轮目标：

1. 让`crt_2`默认人物的完整动作、默认技能及其必要状态分支，在正常训练和已有冒险流程中可用。
2. 新内容沿ACT-03的Godot原生场景、Inspector资源和正式运行链接入，保留人工编辑能力。
3. 修复`crt_1`基础音效漏接与用户反馈的Q错误特效；对新角色逐动作核对声音和视觉资源，减少可由开发自检发现的漏项。
4. 区分基础恢复和后期打磨：**原作已有的基础声音接通、特效引用正确属于本轮要求**；音量、混音、精确时机、伤害/击飞表现精校和主观手感留后期。

- 先检查最新工作区、用户修改、ACT-03交付和相关调用链；当前大量文件未跟踪，不得用Git跟踪状态判断文件可删除或覆盖。不擅自清理、提交、推送。

- 正式作者数据沿用`content/characters`、`content/actions`、`content/components`及`scenes/actors`；生成图集/动画元数据沿用`generated`和catalog。作者资源是可编辑内容的权威来源，不在ContentDB复制一份正式技能字典。
- 音效补迁移须只修改已确认缺失/错误的接线，保留人工调整的动作消耗、冷却、判定、位移和自定义事件。保留首次转换“不覆盖作者文件”的保护；需要补迁移时另做定向、可重复执行且不产生重复事件的处理。
- 原始SWF与`../res/`只读，按需导入本轮依赖，记录来源；不把全提取库搬入Godot。复用现有导入、哈希验证和原生Resource结构。
- 角色2的HP消耗、持续扣血和状态分支可以对现有Resource/执行器作必要局部扩展；不得将耗血技能改为耗MP，也不为此引入通用经济框架。
- 默认初始化以原`DefineSprite_3841/frame_1`为据：武器0、护甲1、饰品0、master0、额外技能解锁0。沿用隔离测试档和静音自动回归，不修改用户正式存档、音量或系统输出设备。

## 3. 分项任务与独立验收

### T1（P0）：补修第二个角色的基础音效与Q特效

**开发目标：** 修复用户已确认的两项基础缺口，解决会继续影响新角色的公共漏接原因。

具体实施要求：

- [x] 对照catalog及原AS/XML，检查`crt_1`默认主动作、派生和独立组件应有的声音；逐项补齐接线，不能只补Q一个声音。
- [x] 复现并核对转换筛选、帧数值类型、动画键匹配、Resource保存与`to_runtime()`后的真实事件。整数/浮点匹配问题目前是待验证原因，须以执行结果确定；修复公共原因并定向补迁移已有作者资源。

- [x] 从实际Q起段、持续段和结束段复现错误，沿`skill_q.tres`、生成动画/图集、buff组件及Battle可见输出定位。保留正确原始关联，只修经证据确认的引用、选帧或变换错误。
- [x] 对补迁移验证重复执行不叠加事件，且已有人工参数/自定义声音不会被重置。

**独立验收标准：** `crt_1`默认动作应有声音的接线有逐项依据，并在正式动作消费链产生正确流/事件请求；Q实际可见素材与原对应效果相符，释放、持续、结束、左右朝向、切角色及重进后不残留错误效果。报告明确区分已定位根因、已修复结果与未验证的听感，不把用户反馈尚未复现写成已修复。
