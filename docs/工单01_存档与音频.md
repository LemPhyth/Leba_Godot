# 工单01 存档与音频基础

本轮由流程层持有唯一的玩家档案和单局状态。`SaveStore` 只负责读取、校验和持久化档案，`AudioDirector` 只负责播放和音量应用，两者不创建独立的金币、HP、MP或关卡进度。

## 服务接口

`scripts/services/save_store.gd` 是 `RefCounted`，用 `preload(...).new(path)` 创建。默认路径为 `user://profile.json`，测试可提供该目录内的独立子路径。

| 接口 | 返回与语义 |
| --- | --- |
| `default_profile()` | 新的初始字典，不与其他调用共享可变对象 |
| `load_profile()` | `{ok, profile, status, message}`；读取本身不写盘 |
| `save_profile(profile)` | Godot `Error`；`OK` 才表示保存完成 |
| `last_message` | 最近一次操作的可定位说明 |
| `last_backup_path` | 本次恢复读取或保留旧数据的路径 |

`load_profile().status` 为 `new`、`loaded`、`recovered`、`invalid`、`unsupported`、`io_error` 或 `invalid_path`。不存在存档时返回 `ok=true` 的初始档案。损坏且无有效备份时返回 `ok=false` 和初始档案；流程层必须展示 `message`，不能将这类结果标成“已成功读取”。

`scripts/services/audio_director.gd` 是 `Node`，加入场景树后使用：

| 接口 | 作用 |
| --- | --- |
| `configure({music:{id:path}, sfx:{id:path}})` | 校验并加载工程内音频目录，成功返回 `true`；目录错误时保留原播放配置 |
| `set_volume(value)` | 应用0至1的整体音量；设置值仍由流程层档案持有 |
| `play_music(id)` | 播放或切换唯一 BGM，同一正在播放的 ID 不重启 |
| `play_sfx(id, from_seconds=0.0)` | 从最多8个播放器组成的音效池播放；起点必须有限、非负且小于音频时长，否则报错并保持现有声音 |
| `stop_all()` | 清除音乐 ID，停止 BGM 和音效，完成信号不会把已停止音乐重新启动 |
| `stop_and_drain(timeout_seconds=1.0)` | 可await的退出接口；停止后用WeakRef观测实际播放对象释放，全部释放返回true，超时报错返回false |
| `snapshot()` | 测试与调试用当前播放状态、循环次数、音量和声音池信息 |
| `error_reported(message)` | 缺失、未登记或无法加载的资源错误；同时有警告日志和 `last_error` |

音乐的自然 `finished` 信号触发从头播放，符合原作 `BGM.onSoundComplete` 后 `start()` 的处理模式。音频资源在configure时复制一次并关闭自身循环，播放时复用；避免高频重复创建流、原生循环与回调重复处理，也不修改共享导入资源。stop_all及退出树时清除播放器stream引用。`AudioDirector` 使用非空间化播放器；本轮没有实现距离衰减或声像定位。

本轮音效来自原时间轴的 `StartSound`：普通动作 sprite4637 第7帧使用4421；技能 sprite4685 第2帧使用4678、第5帧使用4458；敌人 sprite3898 第27帧使用3876；死亡 sprite3897 第13帧使用3896。4458 的原始 `inPoint=3900` 按 SWF 的44.1 kHz时间基换算为 `3900.0 / 44100.0` 秒，由动作事件层传入，不裁切或重编码原音频。来源帧、起点和原左右声道包络保存在 `data/asset_catalog.json` 的 `audio_events`。运行时目前只应用整体音量，尚未还原原声道包络，不能据声音可播放认定听感与原作完全一致。

## 新档案结构

```json
{
  "schema_version": 1,
  "settings": {"volume": 0.65},
  "selection": {"character_id": "crt_0", "mode_id": "story"},
  "progress": {"clears": {}, "gold": 0},
  "unlocks": [],
  "equipment": {}
}
```

`progress.clears` 以场景 ID 为键、非负整数次数为值，`progress.gold` 为非负整数。完成次数与金币不同，流程层只在自身一次性结算成功后变更这些值，再调用保存。角色选择和模式选择是新框架的用户偏好，不宣称与原档案字段一一对应。

0.65为本轮默认音量的临时产品设置，不是从原存档推导的默认值。`unlocks` 和 `equipment` 是结构扩展位置；本轮不据空容器声称解锁或装备系统已还原。未知的 JSON 字段在读取与重新保存时保留，已定义字段仍严格校验类型。计数限于 JSON 可安全表示的整数范围；文件上限为1 MiB，结构深度上限为16层。

单局 HP、MP、敌人对象、动作计时器和碰撞结算不写入档案。重新进入场景应由单局状态重建，不能从这些持久字段恢复残留战斗对象。

## 保存与恢复规则

写入顺序为：验证数据 → 在同目录写临时文件并 `flush` → 回读临时文件 → 保留旧档 → 重命名新档。

- 正常旧档保留为 `.bak`，用于恢复上一次有效状态。轮换更旧的备份时，当前有效档仍在原位置。
- 若旧档已经损坏，后续保存先将其保留为 `.invalid_时间戳`，有效备份不因损坏旧档被覆盖。
- 新档安装失败时尝试将旧档恢复到原路径；若恢复也失败，错误信息明确给出旧数据保留位置。
- 主档缺失而 `.bak` 有效时，可以从备份读取；这覆盖两次重命名之间进程中断的情况。
- 遇到不支持的版本时，读取报错且本版本拒绝覆盖，即使有更旧的备份也不静默回退。
- 路径必须在当前游戏的 `user://` 内，不允许 `res://`、绝对路径或 `../` 逃逸。

这些操作提供可恢复的文件替换流程，不承诺操作系统或硬件在任何断电条件下都能完成持久化。失败产生的临时文件保留供定位，不以删除证据掩盖失败。

## 原存档字段依据与兼容性

原脚本是仓库外 `res/scripts/frame_1/DoAction_2.as`：第19行定义 `saveGame`，第21行打开 `SharedObject.getLocal("CACAO/" + slotName, "/")`；第24至156行保存133个数组槽，第158行 `flush()`。第160行开始的 `loadGame` 按相同数组索引恢复。源存档名还受启动脚本 `slotName` 和加载失败分支影响。

| 原槽位或区段 | 静态确认的字段与本轮处理 |
| --- | --- |
| 0、1、3 | 带武器命名的原字段；精确物品枚举和默认值仍需继续调查 |
| 4 | 难度变量；本轮不直接把这个存档值解释为全部模式规则 |
| 29至40 | 多组首饰字段；类型和完整装备规则待还原 |
| 41 | `_root.골드`，金币；与本轮金币持久化概念对应，但没有自动导入原值 |
| 42至46 | 材料或其他进度字段；保留原名称作为调查入口，未完成全部语义映射 |
| 47 | 自动保存开关；原根帧1的实例按 `t >= 10` 调用保存，适用范围不能推广为全游戏统一周期 |
| 72、96至103、110至118 | 角色、阶位或能力相关字段；未将名称猜测作为解锁条件实现 |
| 85 | 自动画质相关字段；本轮无对应持久设置 |
| 95、119 | 模式或完成状态相关字段；分支条件仍需追踪 |
| 120至127 | 成组任务字段；完整状态机和取得条件待调查 |
| 128至131 | 四个任务进度字段；只确认存在，未迁移任务逻辑 |
| 132 | `_root.my_sound.getVolume()` / `setVolume()`；说明原程序保存音量，本轮采用独立0至1设置 |

未列出的槽位仍可在原脚本中逐项追溯，本轮没有完成全部133个字段的类型、默认值、语义和获取条件字典。新档案不是 Flash LSO 文件，不读写、覆盖或转换原 `SharedObject`，不承诺旧存档兼容。后续若要兼容，需另立字段映射与迁移验收，并保留原档。

## 验证记录

2026年11月11日，使用仓库提供的 Godot `4.6.3.stable.mono.official.7d41c59c4` 执行：

```powershell
& '../tools/Godot_v4.6.3-stable_mono_win64/Godot_v4.6.3-stable_mono_win64_console.exe' --headless --path . --script tests/test_services.gd
```

在 `godot` 目录运行。当前记录为50项检查通过、0失败，机器结果在运行后生成的 `artifacts/service_tests.json`；后续增加音效目录条目会自动增加对应混音检查。

覆盖真实文件保存和跨实例读取、未知字段保留、金币及计数类型校验、NaN拒绝、损坏档与备份、未来版本保护、重命名中断恢复、路径逃逸拒绝、备份目标冲突下的原档保全。测试存档位于独立的 `user://service_tests/run_*`，不使用正式 `profile.json`。

音频测试使用自动生成的短 WAV 原生资源和真实 `AudioStreamPlayer`：自然播放完成后循环、同曲不重启、换曲、20次音效请求下的8声道上限、错误信号、静音以及停止后的无残留。偏移测试覆盖负数、NaN、无穷大、等于时长、超过时长的拒绝和正常偏移播放；错误请求不打断已播放的声部。生成的测试资源只位于被忽略的 `.local/service_tests`。缺失音频与无效偏移警告是有意的负向测试。

两首原作 MP3（`1602.mp3`、`7130.mp3`）已经通过实际加载、切换和 Godot 音频总线 PCM 捕获：播放时均有非零样本，静音后样本全零。分别定位到音乐末尾前0.05秒后，自然结束信号使曲目从头继续播放，循环计数增加。两份工程内音频的文件哈希在测试前后相同。

五条原作音效分别在停止其他播放器、清空捕获缓冲后加载和播放，均捕获到非零 PCM。`skill_fire` 使用实际 `3900 / 44100` 秒偏移，其余四条从头播放。测试输出保留每条声音的偏移、样本数和峰值；这是对资源解码与播放的验证，动作事件时机由整体游戏回归验证。

以上是实际 Godot 文件读取、播放器和混音后端检查，没有人工听感或物理扬声器输出验证，也不代替 HUD、实际操作、死亡结算和场景重进的整体测试。原声道包络的还原、播放与原 SWF 的听感对照仍未完成。

## 音频退出生命周期

快速手动推进战斗后立即退出，曾看到 `AudioStreamMP3/AudioStreamPlaybackMP3` 泄漏提示。独立裸 `AudioStreamPlayer`（不经过本服务）连续100次play/stop也复现：Node已释放，播放对象仍被AudioServer持有。原因是stop把原生对象标成待混音线程删除，释放异步完成；固定0.15秒有时仍不够。该行为与[Godot问题76745](https://github.com/godotengine/godot/issues/76745)及4.6.3源实现相符。

本轮服务改成configure时只复制一次流、stop/exit清stream引用，并提供观测WeakRef归零的 `stop_and_drain()`。正常窗口关闭和玩法测试都等待此接口；超时会明确报错，不返回伪成功。100次快速播放/停止的独立探针重复3次全部归零，最终服务50项、玩法95项无退出泄漏警告。证据汇总在 `artifacts/audio_lifecycle_probe.json`。强制终止或直接调用SceneTree.quit绕过异步退出不属于该保证。

实现使用的官方 API 依据：[FileAccess](https://docs.godotengine.org/en/4.6/classes/class_fileaccess.html)、[DirAccess](https://docs.godotengine.org/en/4.6/classes/class_diraccess.html)、[AudioStreamPlayer](https://docs.godotengine.org/en/4.6/classes/class_audiostreamplayer.html)、[AudioEffectCapture](https://docs.godotengine.org/en/4.6/classes/class_audioeffectcapture.html)。
