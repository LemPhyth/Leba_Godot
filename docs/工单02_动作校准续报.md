# 动作系统校准续报

2026-11-12。沿用工单02的动作优先顺序。本轮集中修复控制帧、玩家受击链和对应显示；没有继续扩展剧情。

## 本轮结论与改动

**X首段确实晚了一帧。** 原4637源4的 `gotoAndPlay(6)` 在同tick跳转，原作受控记录的可见序列是 `1,2,3,6…18`。当前序列已去掉源4独立停留：首次处理显示源1，第6次处理在源8发弹，第17次处理执行源19返回父待机。间隔计数是16个tick，不能把“17次处理”说成17个完整显示间隔。其他已接入动作的原始控制节点和完整采样保存在 `artifacts/leiba02_20261112/action_probe.json`。

**玩家受击通过唯一子时间轴结算。** 旧实现将接触、受击、扣血压成一次函数调用，并按攻击窗口去重；现已拆开：

1. 敌人每个有效重叠tick请求玩家受击，独立处理击退，不直接扣血。
2. `Combatant.request_hurt()` 承接原父状态跳转。同父受击请求保留已有子进度；7176还要求子动画跳源2。
3. 角色0的4686与角色1的4920负责受击帧。观察器读取源2才扣血；取消受击动作就不再保留一个脱离动作的伤害计时器。
4. 场景中的敌人根实例分别轮询同一个玩家标记，内部死亡没有移除根实例，因此根4死敌的观察器仍存在。Expert的难度显示监听器在较早阶段独立轮询，不能无条件合并进敌人伤害。
5. 父时间轴独立放置4689受击闪光：受击源1已可见，源2重定向FX2并触发4688声音，FX8为空白。图集烘入原缩放和橙色glow；运行时只应用角色偏移、根缩放及方向。

当前阶段模型重现已取得的受控样本：新的十夫长受击子显式跳2后可被观察；对已经存在的子动画重定向时，它仍在本轮前进到3。**这是符合样本的调度解释，不是对Flash全部事件顺序的证明。** 没有引入通用Flash虚拟机或第二套战斗Runtime。

**三难度数值作用域已修正。** 6968帧1直接将敌HP和hpm乘1、1.5、2，运行时只在新入场应用一次。根2/4每敌初始HP为200/300/400，根6为400/600/800。难度显示帧2/3替换了带监听器的子元件，因此不能仅看 `hp-1-nan` 就给Master/King额外扣2/3。

## 原作运行证据

运行环境：既有Ruffle0.7.1、原SWF自身25FPS、音量0、内存SharedObject、独立配置和日志目录。未运行原生Adobe Flash。所有探针都在仓库外 `../tools/swf/runtime_probe/`；原SWF未修改。
