# 工单 01 资源接入与派生方法

本轮运行时资源由 `tools/import_runtime_assets.py` 生成，清单是 `data/asset_catalog.json`。当前为 11 组动画、2 张界面/场景图、2 首音乐、5 个音效和 1 个字体，共 21 个输出文件、7,498,009 字节（约 7.15 MiB）。Godot 的导入缓存另计；未导入完整帧库、SWF、AS、字节码、XML 或 FFDec。

## 路径与只读边界

工作区目录 `leba_project/res/` 是完整提取资料，位于 Git 管理的 `leba_project/godot/` 之外。Godot 中的 `res://` 指向后者，不是磁盘上的前者。

| 用途 | 工作区相对路径 |
| --- | --- |
| 原 SWF | `leba/雷巴的冒险EX.swf` |
| 原始帧、图形、声音、脚本 | `res/` |
| 原时间轴与放置矩阵 | `res/structure/game.xml` |
| 已有导出工具 | `tools/swf/vendor/ffdec/ffdec.jar`、同目录 `lib/` |
| 工程运行时子集 | `godot/assets/` |
| 来源清单 | `godot/data/asset_catalog.json` |

转换只读上述输入。角色重渲染使用进程内的 SWF 对象副本及临时目录，既不修改原 SWF，也不在仓库内保存修改后的 SWF。当前源 SWF SHA-256 为 `afef4c43153780e9140eca7234b5af26c4a751596efefeb071d35428435a909d`；若源文件版本变化，导入器会要求重新核对规则后才继续。

## 注册点、裁剪与动画时间

统一使用原作 25 FPS。`frames` 是实际播放序列，`source_frame` 是原时间轴帧号；两者不能混用。例如普通攻击第 5 个显示帧对应源帧 6。运行时的显示与物理更新频率由工程独立控制。

原提取 PNG 的画布源于 FFDec 26.2.1 的 `getRectWithFilters()`。转换器通过已有 FFDec Java API 读取 twips 边界，以 20 twips=1 px 换算，核对 PNG 尺寸。每组动作只取全部选定帧 alpha 包围盒的并集，整组使用同一裁剪矩形；不逐帧居中、不重采样。图集每格留 2 px 透明边。

`pivot = (-bounds.xMin/20, -bounds.yMin/20) - union_crop.xy - parent_offset_px`。`parent_offset_px` 包含嵌套到玩家 6732 或敌人 4030 注册点的原始位移。运行时以 `-pivot` 作为绘制左上角，再应用角色缩放及转向。因此动作切换使用同一原始注册点，不能再以图像底部重新对齐。

每帧保存 `region`、`pivot`、`source_frame` 和 `alpha_bounds`。最后一项只表示相对演员注册点的可见像素范围，不能自动等同于原作攻击判定。原始判定体的几何放在 `source_geometry`，分别记录 4547、1119、3875、4684 的边界、缩放和放置矩阵。玩家注册点与敌人注册点并不都在脚底。

### 修复静态导出中的装备轮换

实际观察完整提取帧后发现：FFDec 静态导出不执行 AS，服装、翅膀和枪械子时间轴会逐帧换款。这是导出限制，不是已确认的原作动作。

已从 `DefineSprite_3841/frame_1/DoAction.as` 核实默认 `스핏압=1`、`스핏무기=0`、`스핏마스터=0`；根帧 2、4 的 `pren=0`。3588 先隐藏 `wing`、`전펙`，只有对应条件才显示。转换器据此在内存副本中将 3572、3588、3597、3602、3610、3641、3674、3678、3679、3688、4543、4632 选择器保留首帧，并去掉 3588 两个默认隐藏实例，再渲染本轮五组角色动作。它们各自的首帧 AS 均写入来源哈希清单。

这是一套已确认默认装备的派生配置，不是通用 AS 执行器，也没有实现换装。`render_profiles.crt0_default_equipment` 记录选择器和默认值。清单仍保留对应原提取帧路径/hash，另记重渲染帧 hash；角色的 `source_canvas_size`、`source_bounds` 是该派生配置渲染画布的尺寸和边界。

弹体也按脚本修复默认变体：1474 的 `속` 是 542，其 `총알` 是 541；两者首帧均 `stop()`，根帧 2、4 默认 `eun=zak=0`，只有特殊条件才选 541 的 2/3 帧。`render_profiles.projectile_default` 将 541、542 固定首帧，保留外层 1474 的十帧位移。因此弹体不再随飞行轮换特殊子弹外观。

默认 542 首帧几何边界为 twips `[-150,-126,147,127]`，包含滤镜边界为 `[-290,-266,287,267]`；全时间轴边界混入其他变体，不能作为默认碰撞体。对应局部矩形 `[-7.5,-6.3,14.85,12.65]` 及外层位移/缩放在 `source_geometry.projectile_default`。其子图只有含透明渐变的可见形状，没有独立隐藏判定元件；滤镜扩边是否影响原 Flash hitTest 尚需实际运行对照。

敌人的判定也应区分：清单原 `enemy_body` 对应 4030 的 `중력몸빵`（重力判定）。3898 的 `행동몸빵`（行动判定）使用 1119，但在 4030 局部的矩形为 `[-55.96760495,-173.622184095,104.77960371,172.400006745]`；近距 `근거리` 为 `[-52.95,-160.25,104.85,172.45]`，自身 scale=(1,1)。这些隐藏判定的 alphaMultTerm=0，不能从角色可见像素推断。

## 生成、校验与扩展

在工作区执行：

```powershell
python godot/tools/import_runtime_assets.py
python godot/tools/import_runtime_assets.py --verify
python godot/tools/verify_sources.py
```

当前验证环境已有 Python、Pillow、Java 25 和本地 FFDec 26.2.1。运行 Godot 游戏不需要这些转换工具；只有重新派生素材才需要。`--inspect-bounds 4544 4685` 可只读调查原始边界。

导入器不覆盖清单之外的既有输出，也不覆盖与上次记录哈希不同的本地输出；遇到缺失源帧、尺寸和边界不符、全透明动画或输入变化会明确报错。它不清理目录，不删除旧工程或原始资源。PNG 与字节复制的音频、字体是确定性输出，重复生成保持内容一致。

新增资源应先核对源事件及播放路线，再增加限定的 `ANIMATIONS`/音频事件选择或独立场景图层；角色若存在 AS 控制的默认显示状态，应建立有证据的渲染配置。新增后重新生成清单并检查 atlas，再由框架的角色/敌人/场景数据引用现有统一运行链。不要复制完整库来回避资源映射。

## 本轮验证与边界

- 自动化：来源清单现为 288 个输入、21 个输出、258 个动画帧；检查 SHA-256、帧矩形、透明边、有限 pivot 和 25 FPS 元数据。生成时再次核对所有使用过的原资料；角色/默认装备版本曾验证重复生成 21 个输出哈希一致，之后弹体默认分支修正重新生成并校验。
- 完整资料检查：`verify_sources.py` 已重新读取 `res/_meta/asset_manifest.jsonl` 的 191,733 个文件、2,982,789,466 字节，全部与原清单哈希一致；原 SWF 声明、288 个运行时来源和 21 个输出也通过。结果写入 `artifacts/source_integrity.json`，未复用旧哈希检查缓存。`res/_meta/` 自身及未列入范围的原 ZIP/辅助程序不冒充已全量校验。
- 图像实际观察：角色五动作、敌人待机/移动/攻击/受击/死亡、弹体、独立森林和标题已查看；修复并复查服装及武器轮换。alpha 与帧画布保留，无逐帧重新居中。
- 五个原声效已由音频服务测试通过真实 Godot 混音 PCM 非零检查，4458 使用 3900/44100 秒起点；音乐、切换及保存测试详见 `工单01_存档与音频.md`。混音输出验证不等同于人工听感或原 Flash 音量对照。
- 未完成原 Flash 运行画面对照。默认显示选择器修复有静态脚本依据，但其他嵌套 AS 特效、滤镜、遮罩和时序仍需运行对照。这里没有承诺逐像素一致。
- 字体不覆盖全部中文字形，且部分标点映射不标准；实际UI使用系统CJK字体优先、源字库fallback以修正显示。源声音的完整左右包络、装备分支、更多角色和场景均未在本轮资源子集中实现。
